# H3 更新记录

## 2026-09-14 · 保留双采的多场景循环修复

- 真实 H3 第二场验证暴露了 CPU 模拟未覆盖的接口差异：MiniMax H3 视频 VAE 解码返回 `[B,T,H,W,C]`，二采衔接节点曾只接受四维 IMAGE，因此首段保存成功后在第二场上一段尾帧重编码时中断。现按 ComfyUI 原生 `VAEDecode` 的合同将视频批次/时间展平为 IMAGE 帧后再缩放编码，并新增五维 VAE 回归。
- 运行状态的 `run_name` 现在与 `run_name_override` 选中的实际检查点目录一致；导演台原始名称仍保留在 `plan.run_name`。这避免互动审片、恢复查找和最终文件名使用不同运行身份。
- 日志确认第二轮抛出 `Node 29.0.0.29 not found`：递归把原始 End 当作旁路输出拼接了不存在的 ID。现在排除 End/有写入副作用的审片旁路，只引用动态图中存在的节点。
- 修复版以安装目录 `example_workflows/eagle_h3_full.json` 为基准，保留全部原节点、四个场景、SolAttn、Chunk FeedForward、预览、学习式 latent 放大及 RTX 增强。新增二采画布/蒙版衔接和独立二采 Guider；单采对照节点保留，但不连接主成片输出。
- 主流程为 `45 去噪预测 → AV 拆分 → 84 latent 放大 → AV 合并 → Eagle 二采适配 → 47 二采 → 解码 → 30 裁剪 → 77 RTX → 86 审片 → 29 循环结束`。保留二采 RandomNoise：这是放大后重新加噪的细化流程，不是同尺寸 DisableNoise 接力。
- 二采适配重新编码目标画布的 `minimax_keyframes`，不修改有独立尺寸的参考素材；恢复放大器丢失的 AV noise_mask。最终 47 的同一 AV 输出用于解码、检查点和下一段接力。
- 86 是唯一保存/审片节点；28 接 86 的 state/clip，仅作只读历史回看。修复递归 pending 事件误投普通面板的问题。刷新后可按运行名称和节点找回唯一待审 token。
- SplitSigmas 不再使用总步数作为切分位置；保留作者设置的独立切分值 4。高级视频保存 FPS 跟随导演台，避免 24fps 的 7 秒片段按 30fps 保存成 5.6 秒。
- 保存失败阻止推进；恢复早先场景时丢弃不对应的运行期尾帧/latent；已完成运行不会在 resume 时悄悄重采最后一场。
- 修复工作流在原运行名覆盖为空时使用 `eagle_h3_dual_loop_v2`，避免续用旧单采检查点；旧视频和检查点保留。后续同一运行中断仍可 resume；另起作品请换运行名称。
- 本轮验证：93 项测试与 28 项子测试通过，前端合同测试通过。真实 ComfyUI PromptExecutor 的 CPU 模拟采样回归覆盖四场景自动运行、逐段批准、同场重试和中途停止；未加载 H3 模型权重。

使用：一次 Queue 内逐场展开，`auto` 保存后自动继续；`interactive` 等待批准/重试/停止。修改后的工作流需要重新打开，前后端更新后建议重启 ComfyUI 并刷新页面。此记录不代表真实 H3 模型/GPU 整链已经验收；双采与放大会增加实际显存和执行时间，原放大倍率未被自动降低。
