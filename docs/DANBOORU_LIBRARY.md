# Danbooru 标签库：使用方法与实现依据

研究日期：2026-09-08。此功能是现有「🦅 Danbooru 标签搜索」的词库管理扩展；同步与模型填充均由用户显式触发，不会在加载节点时自动采集或调用付费模型。

## 先理解三个不同的“分类”

1. **官方类型**：General、Artist、Copyright、Character、Meta。保留 Danbooru 原值，不能用“服装”替换官方类型。
2. **Wiki 标签组**：提供分类线索。正文也包含“参见”等链接，因此解析到的链接只是候选关系，不能不经检查直接认定归属。
3. **Eagle 用途分类**：姿势、身型、表情、服装部件、场景、镜头等；允许一个标签具有多个属性。由模型依据检索资料分配，审核后才进入细分类抽卡。

模型调用不等于联网检索。本实现先通过明确的 API 检索、缓存官方释义，再将资料交给本地模型或在线模型。模型不能自行执行 Wiki 中的指令。

## 节点内如何使用

打开设置 → **标签数据**。新界面会显示首次初始化状态，优先点击「开始首次初始化」或「继续首次初始化」。该流程按“随附词表 → Wiki 标签组 → 官方标签”执行，已完成阶段自动跳过；关闭设置弹窗不影响任务，关闭 ComfyUI 后再次点击可从事务断点续传。

1. 点击「导入已有词表」。当前随附 CSV 实测有 **49,837** 条带中文的标签，不必先重新翻译一遍。原译名来源标记为 `bundled_csv`，不代表人工审核通过。
2. 点击「同步/续传 Wiki 组」，建立多对多的分组线索。
3. 需要扩充名称覆盖面时，点击「同步/续传官方标签」。默认单次 10 页；页数 0 表示一直运行到扫描结束。状态里的 `complete` 才表示**该轮**扫描完成，不能把“已下载一批”当成全量完成。
   一键首次初始化会自动使用 0 页模式直至结束，但只抓取至少关联一件作品的标签和 Wiki 元数据，不下载图片、不加载语义模型、不调用翻译模型。完成以后，打开节点只查询本地库，不会自动重新联网。
4. 在 Danbooru 节点左侧连接一种模型：`local_model` 接 Eagle 本地大模型加载器，或 `api_config` 接 API 配置加载器（也可配置 Ollama 的 OpenAI 兼容地址）。两者同时连接时固定使用本地模型，不会静默切到可能计费的 API。
5. 打开“标签数据”，可先点「检索本批官方释义」，再将「模型补全」由关闭切换为启用。这不是数据库首次校验；开关只表示每次正常执行该工作流时，使用画布已连接模型处理一个有界批次（默认 20，最多 50）。开启时会提交首批；它不会自己反复排队，关闭后不再处理后续批次，已经在推理的当前批不强制中断。
6. 核对译名、属性列表、评级、置信度和依据，逐条采用或拒绝。置信度是模型自评，不是准确率；角色专名尤其需要核对。拒绝项不会立即进入下一批反复消耗模型调用。
7. 点击导出：`eagle_suite/danbooru_engine/library/exports/tag_dictionary.jsonl` 是完整逐行词典；同名 `.md` 是已审核中文词典。

采集可以停止，已完成页面和游标保留。已经发出的模型推理无法通过采集停止按钮取消，需要等待服务返回。不要在采集时同时启动多个 ComfyUI 实例操作同一词库。

### Ollama 如何连接

已在本机 `/api/tags` 确认存在 `gemma4:12b` 与 `qwen3.8:27b`。它们不是 ComfyUI 加载器的模型端口对象：

1. 保持 Ollama 运行。
2. 用「API 配置加载器」新增一个 LLM 配置：Base URL 填 `http://127.0.0.1:11434/v1`，模型名填实际名称，例如 `gemma4:12b`；本地无认证服务的 API Key 可以留空。
3. 将加载器的 `api_config` 输出连接到 Danbooru 节点的同名输入。
4. 打开 Danbooru 设置 → 标签数据，先用 1–3 条执行“使用已连接模型填充单批”，检查草稿后再增加单批数量。

不需要 API Key，但需要上述一根画布连线；不要在地址末尾重复添加 `/v1`。[Ollama 官方兼容接口说明](https://docs.ollama.com/api/openai-compatibility)确认 `/v1/chat/completions` 可用于这种调用。若 ComfyUI 在其他电脑或容器，127.0.0.1 指的是服务所在环境，需要另行配置可达地址与访问控制，不建议直接向公网开放 11434。

本机 12B 模型磁盘约 7.56 GB，27B 约 17.74 GB；磁盘大小不等于推理显存需求。检查时 GPU 仅约 1.1 GB 空闲，故没有加载推理或卸载用户现有模型。当前已验证的是服务发现和模型名称，不是翻译质量。

## 细分类怎样用于抽卡

设置 → **抽卡** → 生成方式选择“本地标签数据文件”，展开“细分类配额”。

- 全部为 0：保留现有普通抽卡逻辑。
- 任一配额大于 0：使用审核通过的细分类池，替代普通大类配额。
- 例如：姿势/站坐卧跪 1，服装/上装 1，服装/下装 1，场景/地点 1，构图/景别 1。
- 不足数量会提示，不使用未审核条目补足。新下载标签没有评级，默认不当作 SFW。
- 输入了固定角色特征时，跳过身份、身材、头发、面部抽取。官方角色标签和画师标签不加入通用随机池。
- 在新细分类模式中，同一词库、配额、输入和非负种子可重复得到相同结果；仅随机种子模式使用近期去重。
- 相同标签不会重复抽中；这**不等于**完整的语义冲突求解。比如同一姿态配额设成 2，仍可能抽到彼此不协调的姿势。基础姿态、视线、景别建议各 1 项。别名归一、互斥关系和共现约束仍是后续工作。

## 保存后的 tag 数据库如何使用

不需要另外放置“数据库读取节点”。`tags.sqlite3` 会被 Danbooru 节点自动用于：

- 左侧本地标签查词：英文名、已审核中文名和 Wiki 释义可查，并按官方类型 Artist / Copyright / Character / General / Meta 筛选。
- 双语与细分类显示：图片标签会补全已审核译名、姿势/服装/构图等属性。
- 关联推荐：已选标签优先查本地共现表，不需要让向量模型猜搭配。
- 本地抽卡：从已审核细分类池中按配额取标签，不将待审核译名当成安全结果。
- 输出与备份：可导出 JSONL 全量数据和 Markdown 已审核子集，便于校对、版本管理或给其他工具导入。

向量编码器的职责是把自然语言查询找到语义相近的标签，它不能单独保证姿势、服装、角色和场景互相兼容。自动搭配优先使用“Danbooru 随机帖子”的同帖共现；本地模式则用已审核分类配额，后续再叠加互斥规则与共现重排。

## 图库排行与内容范围

图库已增加“最新 / 评分热门 / 收藏热门 / 随机”排序，以及最低评分、最低收藏阈值。这些条件使用 Danbooru 正式 `order:*`、`score:*` 和 `favcount:*` 元标签在服务端筛选，不是只对当前已加载的 40 张图做前端排序。

节点只保留与提示词选材直接相关的 Posts、Tags、Artist / Copyright / Character / Meta 分类与 Wiki 释义。Pools 只在用户点击“查系列”时按需查询，选中后用 `pool:<id>` 检索同系列参考图，不做全量同步。Comments、Forum、Notes 等社区内容不采集、不建索，避免把社区讨论噪声引入提示词库。

## 数据与兼容策略

SQLite 文件位于 `eagle_suite/danbooru_engine/library/tags.sqlite3`，属于用户数据，不提交 Git。

- `tags`：官方 ID、名称、类型、热度、废弃状态；保留原有中文表数据。
- `wiki_groups` / `group_links`：原始分组正文与候选标签关系。
- `tag_wikis`：按需缓存的官方释义、其他名称、更新时间。未找到与未检索区别存储。
- `annotations`：模型译名、多重属性、评级、置信度、说明、模型名称和证据版本；分 pending/approved/rejected。
- `audit`：审核前记录。采集不覆盖已审核注释。
- `checkpoints`：每个资源的独立游标，和当前页数据同事务提交。

新增词库不覆盖原 CSV，也不自动重建巨大向量索引。直接/混合搜索可以使用新增英文名称和审核中文；纯语义搜索仍受现有向量库覆盖范围限制。标签保留在 SQLite，不把全站标签传入 Vue 或一次性装入显存。

文本正文不会按字符数截断；模型上下文窗口和输出 token 容量仍是物理限制。输出截断、JSON 错误、额外标签、未知分类 ID 或不合法置信度会拒绝整批写入；此时减少单批条数重试。

## 访问策略：温和采集，不承诺“永不封禁”

[Danbooru 官方 API 说明](https://safebooru.donmai.us/wiki_pages/help:api)建议长期读取约每秒 1 次。本实现默认单线程、每次请求至少间隔 3 秒，再增加 0–1 秒抖动；每 25 页额外休息约 15 秒。参数可在“Danbooru 连接 → 词库同步节奏”调整，但代码强制基础间隔不得低于 2 秒。公开元数据请求使用真实工具标识，不轮换账号、代理或浏览器指纹。

首次同步完成后不会在每次加载节点时重复联网。界面默认 30 天后仅显示刷新提醒，仍由用户手动启动完整刷新；这能避免多个工作流或多个 ComfyUI 实例意外重复扫描。

429 / 5xx 有限退避，遵守 `Retry-After`；等待要求过长则停止，留待稍后继续。401 / 403 / 重定向 / 非 JSON 验证页直接停止。用户已配置的固定网络代理仅用于正常联网，不作为拦截后的自动换出口机制。节点既有图片浏览请求尚未和本采集器共享限速器，采集期间请避免大量并行翻页。

[标签接口](https://safebooru.donmai.us/wiki_pages/api:tags)与[分页说明](https://safebooru.donmai.us/wiki_pages/help:common_url_parameters)支持 ID 游标。采用降序 ID 和 `page=b<ID>`，不依赖容易到达上限的深页码；同时传递官方 `search[hide_empty]=true` 条件，跳过没有关联作品的空标签。结束后重跑从头刷新旧条目的热度、类型、废弃状态；这是**可续传的非空标签全扫描**，还不是按修改时间同步所有删除/改名的精确增量镜像。

未确认一个稳定可用、许可明确的当前官方全量导出链接，所以没有把历史快照地址当作默认下载源。

## GitHub 调研结论

- [WeiLin-Comfyui-Tools](https://github.com/weilin9999/WeiLin-Comfyui-Tools)：主项目使用 GPL-2.0；其[独立提示词数据仓库](https://github.com/weilin9999/WeiLin-Comfyui-Tools-Prompt)标为 MIT。实际查看 `tags/2025_03_31/tags_2025_03_31.sql`，包含 10 大类、131 子类；可借鉴人物部位、服饰结构、物件交互等维度。本次独立实现分类机制，没有执行或导入外部 SQL，也没有复制主项目代码。该词库包含自然语言提示词，不应一律认定为官方有效标签。
- [danbooru-tag-pipeline](https://github.com/SuzumiyaAkizuki/danbooru-tag-pipeline)：验证了标签同步、Wiki 分组、模型增强分阶段处理的方向。没有整包复制；现有 Eagle 的 CSV 字段与其输出结构相近，但不据此声称当前 CSV 有可核验的完整来源链。
- [danbooru-tag-index](https://github.com/Jannchie/danbooru-tag-index)：提示 Wiki 别名不必然等于准确译名；角色/作品名应与通用词汇区别处理。这里将原始资料与可审核注释分开，避免自动覆盖。
- [a1111-sd-webui-tagcomplete](https://github.com/DominikDoom/a1111-sd-webui-tagcomplete)：适合参考补全与别名用法，但“补全词表”本身不能代替细分类和语义互斥知识。
- [Danbooru WikiPage 源码](https://github.com/danbooru/danbooru/blob/master/app/models/wiki_page.rb)：用于核对字段、标题查询和分组处理方式。

## 本轮执行结果与边界

2026-09-08 已在实际 ComfyUI 数据库完成首次扫描：官方标签游标抵达空页，检查点 `complete=true`，共写入 1,112,263 条官方记录；与随附词表合并后共有 1,113,019 条，其中 1,078,154 条为非空且未废弃的可用标签、49,837 条已有中文译名。`tag_group:*` Wiki 分组共 110 组并已完成。数据库 `PRAGMA integrity_check` 返回 `ok`，文件约 132.5 MiB。首次扫描窗口约 80.9 分钟，包含主动暂停、补丁验证和定期长休息。

在前 121,000 条断点之后启用了官方 `hide_empty` 过滤；数据库因此保留了此前已合法取得的 34,730 条零作品历史记录，但搜索与抽卡查询均明确排除它们，后续请求也不再抓取空标签。没有为追求整齐数字破坏性删除用户库记录。

实际验证：124 项 Python 离线测试、前端 JavaScript 语法检查、API 配置/生图模拟 UI 测试和 Vue 节点框架测试均通过。官方 Wiki 的默认顺序是更新时间，不能直接用于 ID 断点；已使用强制 ID 顺序的顺序分页，并校验每页顺序和标题过滤结果。没有执行全库翻译或浏览器端人工交互验收。

已实现可续传采集、官方释义缓存、画布本地/API 双模型入口、草稿审核、细分类抽卡和词典导出。旧设置字段仍保留给既有工作流和 AI 抽卡兼容，但新的词库填充不再依赖隐藏的模型来源设置。这里的“完成”只表示官方原始标签/分组同步完成，不表示全部标签已经翻译或完成人工细分类。没有自动安装 WeiLin，没有运行外部仓库脚本，没有启动全库付费任务。

下一阶段可扩展：自定义分类编辑器、批量审核与返修、官方 alias/implication 同步、释义版本变化后的复核、互斥/共现约束、语义索引增量更新。分类细并不自动保证随机组合协调，这些应分别验证。
