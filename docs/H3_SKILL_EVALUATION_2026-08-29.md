## 仍存在的生产级缺口

1. **分镜结果没有真正喂给台词任务。** `run_director_skill()` 虽然把生成分镜写入 `cur["shots"]`，但 dialogue 模板只注入 `preamble`，没有注入 `shots`。当前模型仍能从台本抽取正确台词，但“台本 → 分镜 → 台词”的最后一段数据链并未完全实现。
2. **最终 H3 prompt 存在内容重复。** script 生成的 `preamble` 已包含完整 `[Shot N]` 描述；shots 又把相同内容结构化。`_build_scene_prompt()` 同时输出 preamble 与 detailed shot blocks，会让最终提示词重复同一镜头描述，增加 token 并可能造成模型强调过度。
3. **缺少生成后校验/修复。** 当前实现直接信任模型 JSON。本次模型恰好满足 18 秒、字段和时间码约束，但换模型后没有自动归一化时长、重排时间码、补必填字段或二次修复机制。
4. **任务顺序未在后端强制规范化。** 后端按 request 中的 tasks 顺序执行；正常 UI 会给出合理顺序，但外部调用或旧状态可以传入 `dialogue → shots → script`，破坏链式依赖。
5. **单场景提示词偏长。** 本次 18 秒台本约 1785 字符，再叠加结构化分镜与声音块后明显冗余。结构正确，但生产效率与提示聚焦度仍有优化空间。

因此，本次模型的**结构完成度为 100%**，场景与技能的**内容匹配度约为 95%**；考虑数据链、重复编译和缺少后处理，当前整体**生产稳健度约为 82%–88%**。

## 节点收敛建议

当前注册 20 个 H3 类节点（含导演台、媒体端口与 18 个流水线节点），主菜单对普通用户偏零散，但没有同一类重复注册。建议按三层呈现：

- 核心流程：导演台、媒体端口、流水线入口、镜头准备、检查点+审片、原生结束+合成。
- 可选工具：载入清单、裁剪、PNG 序列、接缝探测、智能分镜。
- 旧版兼容：分段+检查点、审查门、结束、合成。

可进一步组合：

- `计划预检 + 链·计划 + 原生循环·开始` → “H3 流水线入口”。
- `当前镜头 + 上下文` → “H3 镜头准备”。

这样推荐新工作流可从约 8 个 Eagle 节点收敛到约 5–6 个，同时保留高级用户拆分接线与旧工作流兼容。
