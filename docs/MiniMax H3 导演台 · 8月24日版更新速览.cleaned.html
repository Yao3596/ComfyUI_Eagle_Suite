UPDATE LOG · 2026-08-24 · 合集 18/21

MiniMax H3 导演台 · 本期更新速览

两大新功能 + 一个关键 Bug 修复：选择已有素材 · 参考图尺寸可选 · 换视频串段引用修复。升级方式：将 ComfyUI MiniMaxH3 Director 插件更新至最新版。

修复前 修复后 实际好处
1

「选择已有」素材复用

社区 PR + 维护者交互改良

■ 之前

参考图 / 视频 / 音频每次都只能手动重新上传或拖拽导入，无法调用已经上传到 ComfyUI 里的素材；多片段、多角色项目要反复传同一批文件。

■ 现在

所有素材入口（图生视频、首尾帧、R2V、RV2V）都新增「选择已有」按钮 → 弹出素材选择框，带预览图列出已上传素材 → 双击或点「使用所选的文件」即完成引用。
好处：素材一次上传、全程复用，省去重复传图的时间与误操作；预览图让挑选不再靠猜文件名。
适用：图片 / 视频 / 音频 全类型 设计取舍：保留「上传」为主入口，不强制弹选择框，避免每次多一步
2

参考图尺寸可选

R2V / RV2V 模式

■ 之前

导演台里参考图尺寸被固定为默认「match（匹配）」，不可修改；而官方工作流本来就提供两种尺寸选项。

■ 现在

R2V（参考主体生视频）与 RV2V（参考素材改视频）两种模式下，均可像官方工作流一样自由选择参考图尺寸。
好处：尺寸不再被锁死，输入分辨率可以匹配任务需求，直接影响生成速度与画质表现——这是本期含金量最高的一项。
评论区实证 · 青离剑仙：“用工作台一直生成的很慢，直到这一版更新完，终于速度正常了，原来是参考图输入的尺寸问题。” —— 说明此前固定 match 尺寸确实拖慢过实际生成。
3

换视频后串段引用 Bug 修复

V2V / RV2V

■ Bug 场景

智能分割或均分后，只运行了第 3 段；随后更换一个新视频重新分成 5 段——点「选择运行」时，第 3 段仍会自动引用上一个视频的产出结果，新旧结果串用，直接产出废片。

■ 修复后

更换视频重新分割后，各分段正确绑定当前视频的结果引用；V2V 与 RV2V 两处同源问题一并修复。
视频 A · 分割 7 段
运行第 3 段
→
换视频 B · 重新均分 5 段
→
✗ 修复前：第 3 段误引视频 A 的结果
✓ 修复后：正确引用视频 B
好处：保证结果正确性——分段编辑、挑选运行的迭代流程里不再混入旧素材，避免整批废片重跑。
遗留问题（评论区仍在反馈）：二采速度偏慢（有人 3 步跑 1 小时）、素材过多时内存溢出（Linux 环境生成 4 段 15 秒即 OOM）、多镜头缓存体积大（30 镜头约 50G）、音画同步偶发延迟。
值得注意的更新模式：「选择已有」来自网友 PR，UP 主保留主入口、只加侧按钮做交互改良——社区贡献 + 维护者 review 的开源协作，是这个插件两天一更仍能保持体验不劣化的原因。
